# TrustNews async flows

## BLOCKCHAIN mode sequence

```mermaid
sequenceDiagram
    autonumber
    participant C as Client / Frontend
    participant H as news-handler
    participant A as admin
    participant K as Kafka
    participant G as generate-asertions
    participant I as ipfs-fastapi
    participant P as IPFS
    participant N as news-chain
    participant S as Smart contract
    participant V as validate-asertions
    participant E as evidence-search
    participant M as MongoDB

    C->>H: POST /publishNew validation_mode=BLOCKCHAIN
    H->>A: Check news_generation quota
    A-->>H: Quota status
    H->>M: Create order status=CREATED
    H->>K: generate_assertions
    K-->>G: Consume generate_assertions
    G->>G: Build prompt and parse Assertion list
    G-->>K: assertions_generated with assertions-document-v2
    K-->>H: Consume assertions_generated
    H->>A: Check/increment quotas
    H->>M: Store assertions_document status=DOCUMENT_CREATED
    H->>K: upload_ipfs(document)
    K-->>I: Consume upload_ipfs
    I->>P: Store assertions-document-v2
    P-->>I: CID
    I-->>K: ipfs_uploaded
    K-->>H: Consume ipfs_uploaded
    H->>M: Store CID status=IPFS_UPLOADED
    H->>K: register_blockchain(text, cid, chain_assertions)
    K-->>N: Consume register_blockchain
    N->>S: registerNew(cid, categoryIds)
    S-->>N: RegisterNewResult(postId, validatorAddressesByAsertion)
    N-->>K: blockchain_registered
    K-->>H: Consume blockchain_registered
    H->>M: Store postId, validators, validators_pending
    S-->>V: ValidationRequested(postId, assertionIndex, cid)
    V->>I: GET /ipfs/{cid}
    I->>P: Read document
    P-->>I: assertions-document-v2
    I-->>V: assertions-document-v2
    V->>V: Build assertion-validation-payload-v2
    opt Validator type is RAG_EVIDENCE_VALIDATION
        V->>E: POST /search/evidence
        E->>M: Read/write evidence cache and domain profiles
        opt Cache miss and Tavily configured
            E->>E: Resolve domains from category/subcategory/context
            E->>E: Query Tavily
        end
        E-->>V: evidence-search-response-v2
    end
    V->>V: Call LLM and parse ValidatorAPIResponse
    V->>S: Register validation transaction
    S-->>N: Validation event / chain read
    N-->>K: validation_completed
    K-->>H: Consume validation_completed
    H->>M: Store validation, decrement pending, recalculate results
    H-->>C: GET order returns status/assertion_results
```

## LIGHT mode sequence

```mermaid
sequenceDiagram
    autonumber
    participant C as Client / Frontend
    participant H as news-handler
    participant A as admin
    participant K as Kafka
    participant G as generate-asertions
    participant N as news-chain
    participant V as validate-asertions
    participant E as evidence-search
    participant M as MongoDB

    C->>H: POST /publishNew validation_mode=LIGHT
    H->>A: Check news_generation quota
    A-->>H: Quota status
    H->>M: Create order status=CREATED
    H->>K: generate_assertions
    K-->>G: Consume generate_assertions
    G->>G: Build prompt and parse Assertion list
    G-->>K: assertions_generated with assertions-document-v2
    K-->>H: Consume assertions_generated
    H->>M: Store local assertions_document status=DOCUMENT_CREATED
    H->>N: GET /blockchain/validators?recover_ipfs=true on startup/cache refresh
    N-->>H: Validators with categories, type, config, status
    loop For each assertion
        H->>H: read categoryId
        H->>H: Select active automatic validators for category
        loop For each selected validator
            H->>K: light_validation_request with assertion-validation-payload-v2
        end
    end
    H->>M: Store validators, validators_pending
    K-->>V: Consume light_validation_request
    V->>V: Process only if validator_id == ACCOUNT_ADDRESS
    opt Validator type is RAG_EVIDENCE_VALIDATION
        V->>E: POST /search/evidence
        E->>M: Read/write evidence cache and domain profiles
        opt Cache miss and Tavily configured
            E->>E: Resolve domains from category/subcategory/context
            E->>E: Query Tavily
        end
        E-->>V: evidence-search-response-v2
    end
    V->>V: Call LLM and parse ValidatorAPIResponse
    V-->>K: light_validation_completed
    K-->>H: Consume light_validation_completed
    H->>M: Store validation, decrement pending, recalculate results
    H-->>C: GET order returns status/assertion_results
```
